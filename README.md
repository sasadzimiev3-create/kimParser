# kimparser

Слушает выбранные чаты на аккаунте Telegram и пересылает оригинал сообщения в личку с ботом, если в тексте есть один из общих ключей.

## Где лежит

- Код: [sasadzimiev3-create/kimParser](https://github.com/sasadzimiev3-create/kimParser)
- Сервер: `/opt/kimparser` на `31.76.53.4`
- Рядом, но это другие проекты и их нельзя трогать: `/opt/coffedzhim`, `/var/www/coffedzhim`, `/opt/izicrm`

Выкат копирует только эту папку и не занимает порты 80, 3000, 8787 и 5432. Своего сайта и nginx-конфига у парсера нет.

## Как это будет работать

1. На аккаунте-слушателе есть папка Telegram, например `Парсер`. В неё вручную добавлены чаты, без галочек «все группы» и «все каналы».
2. Процесс на Python (Telethon) читает эту папку и слушает новые текстовые сообщения.
3. Ключи общие для всех чатов. Фраза ищется внутри текста без учёта регистра.
4. При совпадении аккаунт пересылает оригинал в личный чат с ботом. Бот ничего не отвечает, это просто чат назначения.
5. Правки сообщений и подписи к фото или видео в первой версии не смотрим.

Аккаунт уже должен состоять в каждом чате. Папка сама никуда не вступает.

## Что нужно до кода слушателя

- `api_id` и `api_hash` с [my.telegram.org](https://my.telegram.org). С этого сервера Telegram создание приложения отклоняет, нужен домашний или мобильный IP.
- Номер аккаунта, который сидит в чатах. Первый вход попросит код из Telegram. Сессия останется на сервере и в git не попадёт.
- Username бота, созданного в @BotFather. Токен бота для первой версии не нужен.
- Имя папки и список ключей.

## Порядок реализации

1. Конфиг: имя папки, ключи, username бота. Секреты только в `.env`.
2. Разовый вход аккаунта и файл сессии.
3. Чтение папки Telegram и обновление списка чатов, когда папку меняют.
4. Фильтр новых сообщений и пересылка оригинала боту.
5. Отдельный systemd-юнит `kimparser`. Перезапускается только он.

Пока ключей API нет, сервис не запускаем.
